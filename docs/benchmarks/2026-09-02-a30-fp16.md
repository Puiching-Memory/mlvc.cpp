# NVIDIA A30 FP16 backend baseline - 2026-09-02

This is the first four-backend model-level baseline, not a full codec
benchmark.

## Setup

- GPU: NVIDIA A30, SM80, 24 GiB
- CUDA toolkit: 13.3
- Backends: ONNX Runtime 1.26.0, libtorch 2.13.0 cu130, TensorRT 11.2.1,
  Driver+cubin
- Model: `dmc61sbr_reglu`, official `mlvc-psnr-v1.ckpt`
- Model size: 640x368
- Input: one 640x360 neutral-gray YUV420 frame
- Q index: 21
- Floating-point precision: FP16 only; control input: int32
- Timing: 20 warm-up runs, 100 measured runs
- Scope: host input through host output, including H2D, D2H, allocation, and synchronization
- ONNX export: NVIDIA-only passes (`onnxscript_optimizations`, `use_space_to_depth`,
  `depth_to_space_crd_to_dcr`)

GPU clocks were not locked and no concurrent-load isolation was applied. Treat
p95/p99 as preliminary.

## Driver+cubin optimization

The initial Driver+cubin profile spent 98.9% of CUDA kernel time in the generic
convolution kernel. Pointwise convolutions accounted for 60.47 of the encoder's
63.95 GFLOP and 63.27 of the decoder's 66.18 GFLOP. The optimized path adds:

- four-warp WMMA pointwise convolution with FP16 inputs and FP32 accumulation;
- WMMA implicit-GEMM spatial convolution without a materialized im2col buffer;
- a direct, barrier-free depthwise convolution kernel.

All other convolution shapes retain the generic fallback. The same 20/100
benchmark before and after these changes measured:

| Model   | Generic mean ms | Optimized mean ms | Speedup |
| ------- | --------------: | ----------------: | ------: |
| Encoder |        244.8031 |           12.7472 | 19.204x |
| Decoder |        251.4018 |           12.6680 | 19.845x |

## Accuracy

The reference is the upstream PyTorch conversion-loop output rounded to FP16.

All four backends produced numerically exact `z_raw`, `y_raw_0`, and `y_raw_1`
for this case. Their raw half bits differ only for signed zero, which does not
change the numerical latent value.

| ONNX Runtime |                   0.000488 |     0.000196 |     0.000421 |

The generic upstream ONNX pass set initially split large gated convolutions.
That version produced three numerically different TensorRT `z_raw` values and
an encoder feature RMSE of 0.016957. Removing the cross-platform channel-split
and QNN workaround passes restored exact numerical latents, reduced feature
RMSE to 0.000886, and reduced TensorRT encoder mean latency from 4.47 ms to
3.71 ms.

## Conclusions

- TensorRT is about 1.7x to 1.9x faster than the framework backends in this
  host-roundtrip microbenchmark.
- ONNX Runtime is slightly faster than libtorch in this rerun.
- Optimized Driver+cubin is about 3.0x to 3.1x slower than TensorRT and 1.8x
  slower than ONNX Runtime, down from 64x to 66x behind TensorRT.
- Driver+cubin retains the shortest model load time.
- TensorRT has about 2.1x to 2.7x the feature RMSE of the other backends, but
  reconstructed-frame error remains close.
- Entropy-critical latents are numerically exact for this one frame and Q index.
- No codec-level bitstream, GOP, rate-distortion, or multi-sequence claim is justified yet.

## Optimization Headroom

1. Autotune Driver+cubin WMMA tile shapes, stage tiles asynchronously on SM80+,
   fuse adjacent bias/activation/residual operations, and capture the static
   schedule with CUDA Graphs.
2. Keep DPB, feature, and reconstructed tensors on the GPU across frames.
3. Add ONNX Runtime I/O binding and persistent CUDA buffers.
4. Keep libtorch inputs and outputs as native CUDA tensors instead of rebuilding
   host-backed tensors per call.
5. Expose direct device buffers in the TensorRT backend and remove per-call
   H2D/D2H copies and stream synchronization.
6. Add CUDA Graph capture to the framework backends after fixed-shape
   device-resident execution exists.
7. Repeat accuracy testing across real sequences, Q indices, frame types, resets,
   and long-term-reference states before setting release thresholds.

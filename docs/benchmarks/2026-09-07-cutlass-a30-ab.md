# CUTLASS 3.4.1 vs 4.8.0dev on A30

## Conclusion

On the tested driver-cubin FP16 workloads, upgrading CUTLASS alone produced
only a small measured latency reduction (0.02%-0.31%), not a material speedup.
All 12 saved model output tensors were bit-identical between versions. Both
profiles passed full codec conformance with identical recorded error metrics.
There is no observed accuracy improvement or regression in these fixtures.

These results apply to the current SM80 C++ kernels on A30, not to newer
architectures, CuTe DSL kernels, other resolutions, or other video content.

- Both builds: Release, C++20, IPO off, embedded models on, same source and

- Both fatbins contain sm_75, sm_80, sm_86, sm_89 and compute_89 PTX.
- The embedded model blobs have the same SHA-256:
  `fc3070933caacfa66277cc5150a82bf039e583b19645e5830c347bf2352746da`.

GPU 0-3 were busy with unrelated work; GPU 4 was selected because it was idle.
The reported run pins the process to CPU 11, on GPU 4's NUMA node, using
`taskset -c 11`. GPU clocks were not locked and the shared host was not
reserved exclusively. Small residual timing fluctuations remain possible.

## Method

Use `mlvc_backend_bench` with the existing `gray-q21` and `mlvc-s-gray-q21`
Encoder/Decoder fixtures. Neural-network tensor dimensions are 640x368.
Each process performs 50 warm-up iterations followed by 200 measured iterations.
Run six paired rounds per case, alternating old/new and new/old execution order.
Versions never run concurrently. Compare the median of each version's six p50
measurements; change is `(new / old - 1) * 100`, so negative means faster.

Timing covers synchronous host input to host output, including transfers and
graph execution. It excludes model loading, process startup, rANS coding and
the full CLI video pipeline. These are model inference timings, not end-to-end
codec FPS or GPU-only kernel timings. Input tensors are fixed across iterations.

An initial unpinned batch showed a substantial common latency shift during the
run. Its data was retained in `build/cutlass-ab`, but is not used for the table
below. The entire six-round experiment was repeated with CPU affinity; no rounds
were dropped from that repeat.

## Accuracy

- All 12 output tensors (four per encoder, two per decoder) have identical raw
  file SHA-256 hashes between versions on the benchmark fixtures.
- Within each version, reference-comparison metrics are identical across all
  six timing rounds.
- Full codec tests pass for both versions and both profiles: encode, decode
  the official reference bitstream, decode the backend's own bitstream, and
  compare intermediate tensors and reconstructed YUV against the reference.
- The complete conformance result JSON is identical between versions for each
  profile, including encoded payload hashes and reconstruction error metrics.
- Conformance video: 640x360 gray input, padded to 640x368 for the model,
  Q21, two frames. Only frame 0 is required to be bit-exact to the official
  encoder; frame 1 remains subject to the existing reconstruction/tensor contract.
- Maximum YUV sample error against the official reconstruction is 1 for both
  profiles. Reference-bitstream decode PSNR is 65.0986/65.7055 dB for MLVC
  and 61.4134/62.6398 dB for MLVC-S, for frames 0/1 respectively.
  These PSNR values compare backend reconstruction to reference reconstruction,
  not reconstruction to the source video.

## Local Artifacts

- `build/cutlass-ab-3.4.1`: baseline build.
- `build/cutlass-integration`: candidate build, still using the Git submodule.
- `build/cutlass-ab/run_comparison.py`: experiment runner.
- `build/cutlass-ab-pinned/metadata.json`: toolchain, topology, source diff,
  GPU state, CPU affinity, and binary/model hashes.
- `build/cutlass-ab-pinned/runs/`: 48 individual benchmark JSON files and logs.
- `build/cutlass-ab-pinned/conformance/`: four full codec result JSON files/logs.
- `build/cutlass-ab-pinned/outputs/`: raw tensors used for bitwise comparison.
- `build/cutlass-ab-pinned/summary.json`: aggregated latency and accuracy results.

These build artifacts are local and gitignored. To repeat measurements with the
existing binaries into a separate results directory:

```sh
env CUTLASS_AB_OUT=build/cutlass-ab-repeat \
    taskset -c 11 python3 build/cutlass-ab/run_comparison.py
```

The baseline fatbin was compiled directly with the same nvcc flags as
`backends/driver_cubin/tools/build_fatbin.sh`, replacing only the CUTLASS include
path with `/usr/include`, then embedded by its separate CMake build. No production
dependency override was added. Rebuilding that fatbin through the ordinary CMake
rule would use the new submodule again; recreate the old-version fatbin explicitly
before repeating an experiment after source changes or a clean build.

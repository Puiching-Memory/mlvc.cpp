# MLVC codec compatibility contract

This document defines compatibility for the fixed-shape `dmc61sbr_e1d1`
runtime. Passing a model microbenchmark alone is not codec compatibility. The
Driver+cubin runtime must pass the complete `mlvc_codec_compatibility` target for
both registered profiles.

## Model identity

The supported profiles are:

| Profile          | Model version         | 640x368 feature/y/z channels |
| ---------------- | --------------------- | ---------------------------- |
| `mlvc-psnr-v1`   | `dmc61sbr_reglu`      | `256/128/128`                |
| `mlvc-s-psnr-v1` | `dmc61sbr_mini_reglu` | `96/48/48`                   |

`models/profiles/profiles.json` binds each profile to its checkpoint hash and
construction parameters. A deployment model directory is one canonical
bundle produced by `python -m mlvc_tools.package assemble` from the direct-checkpoint compiler.
Metadata, PMFs, and AOT schedules must describe the same registered checkpoint.

The bundle manifest records the SHA-256 and size of every graph, weight blob,
PMF, and metadata file. `metadata.pb`, `gaussian_pmf.pb`, and
`bit_estimator_pmf.pb` are generated from FP32 checkpoint parameters before
the neural model is converted to FP16. AOT graph schema 3 retains native pixel
shuffle/unshuffle channel order. The compatibility runner rejects any bundle/reference identity or
artifact-hash mismatch before inference.

## Normative bitstream behavior

The container identifier is `mlvc-nalu-v0`, implementing the MLVC v0.x Annex-B
NALU bitstream format derived from [`microsoft/libmlvc`](https://github.com/microsoft/libmlvc)
(MIT License; see `licenses/libmlvc/LICENSE`):

- 4-byte Annex-B start codes (`0x00 0x00 0x00 0x01`), EBSP emulation-prevention
  bytes (`0x03`), and RBSP trailing stop-bit byte alignment.
- Parameter sets `SPS` (NALU type `33`, encoding version `0.1`, model
  width/height div2, `transpose_flag`, `crop_*_div2`,
  `max_temporal_layers_minus1`, `frame_idx_bits_minus8`) and `PPS` (NALU type
  `34`, `init_qp_minus26`) precede every `IDR_N_LP` frame (`20`).
- Coded P/recovery frames use VCL NALU types `TRAIL_R` (`1`) / `TSA_R` (`3`)
  (with non-reference `TRAIL_N` / `TSA_N` accepted by the decoder) carrying
  `qp_delta`, optional LTR slots, `cur_frame_idx`, `ref_frame_idx`,
  `feature_reset_flag`, and the byte-aligned rANS entropy payload.
- Bitstream QP (`init_qp_minus26 + 26 + qp_delta`) is strictly validated in
  `[0, 51]` (`kMinBitstreamQp`..`kMaxBitstreamQp`).

The entropy identifier is `canonical-pmf-v1`. Given identical integer-valued
`z_raw`, `y_raw_0`, and `y_raw_1` tensors, the C++ and Python implementations must produce the same
rANS payload (and identical NALU Access Units on key/first frames) and decode
it identically.

The official Python reference's first frame Access Unit (including `SPS`, `PPS`,
and `IDR_N_LP` bytes) is required to be bit-exact. A
recurrent P-frame payload is not required to be byte-identical against the Python
reference: small legal FP16 differences in the preceding feature DPB can cross
a rounding boundary and change integer latents. Such a stream is still
conforming only if it decodes successfully with the canonical PMFs and its
round-trip reconstruction meets the rules below.

## Reconstruction and tensor rules

References are generated by `python -m mlvc_tools.reference` from the original
checkpoint using the pinned `microsoft/mlvc` eager-Python split-model
implementation, packaged into `mlvc-nalu-v0` Annex-B Access Units. The standard fixture contains two
frames: frame 0 starts with a zero reference (I-frame), and frame 1 consumes
the previous feature (P-frame). This exercises preprocessing, QP shifting,
encoder DPB, entropy coding, NALU encapsulation, decoder DPB, and reconstruction. The portable
C++ test additionally checks the 64-frame GOP wrap and I-frame reset schedule.

The runtime must satisfy all of the following:

- Decode the canonical Python stream and decode its own encoded stream (both
  with explicit `--width`/`--height` and auto-detected from `SPS`).
- Produce the requested frame count and preserve each frame's unshifted QP in
  `[0, 51]`, display dimensions, `frame_type`, and `cur_frame_idx` in the NALU
  container.
- For both canonical decode and self round trip, have maximum YUV sample error
  at most `1` and per-frame PSNR at least `60 dB` against Python.
- Match all `int32` control tensors and preprocessed `x` tensors exactly.
- Match frame-0 quantized latents exactly.
- Keep enforced FP16 feature, reference-feature, and reconstruction tensors at
  maximum absolute error at most `0.25` and RMSE at most `0.007`.
- Emit and consume the Python reference feature on frame 1 within those tensor
  limits; this is the explicit recurrent-DPB check.

P-frame encoder quantized latents are recorded for diagnosis but do not use a
numeric tolerance because one rounding-boundary difference can be integral.
Their correctness is instead covered by rANS decode and the self-round-trip
reconstruction requirement.

## Running the target

Generate references for both profiles with `python -m mlvc_tools.reference --checkpoint`
(see the README), and place them under
`models/fixtures/references/<profile>/gray-q21-2f`. Configure a build with
`BUILD_TESTING=ON`, then run:

```bash
cmake --build build/driver-cubin-release --target mlvc_codec_compatibility
```

The target reports a missing-fixture error until both reference manifests
exist. Individual tests can be run with:

```bash
ctest --preset driver-cubin-release -L conformance
```

`tests/conformance/run_codec_conformance.py --result result.json` writes all payload sizes,
per-frame YUV metrics, and per-tensor errors for audit. This target exercises the Driver+cubin runtime.

For long-sequence audits, generate a longer checkpoint-based fixture and pass
`--diagnostic` to the runner. It records all frame and tensor measurements with
`contract_passed=false` when violations occur, rather than stopping early. This
mode does not relax the normal gate. Two-frame conformance does not establish
long-sequence, arbitrary-content, visual-quality, or rate-distortion acceptance.
Historical results from different execution paths do not accept this runtime.
